A Playbook is a versioned document, not a flat list of entitlements. Its envelope
identifies the artifact, tenant, environment, and schema version; its body holds
policy, targeting, and presentation. This map describes the 29 top-level body
keys in the schema pinned by SDK 0.12.5 documentation (`0.1.524`). Their key set
also matches the scaffold source reviewed on October 23, 2026.

## The main reference paths

Arrows point from a record that contains a reference to the record it names.
This overview groups related fields; the tables below provide their exact names.

## Body field inventory

“Array” means a collection of records, not a promise that each record is an
independent runtime entity. Optional fields may be absent. Compatibility and
authoring-only fields are not instructions to build new integrations around them.

| Field | Shape | Purpose |
| --- | --- | --- |
| `plans` | Array | Base plan definitions, identified by `unique_handle`. |
| `addons` | Array | Add-on definitions referenced by entitlement targets. |
| `entitlements` | Array | Named access or parameter capabilities and their kinds. |
| `entitlement_rules` | Array | Rules binding an entitlement to plan/add-on targets and optional segments. |
| `segments` | Array | Named targeting predicates over context. |
| `content_ui_paths` | Array | Authored CTA action definitions and routing parameters. |
| `slot_configs` | Array | Deprecated compatibility field; activation/trigger state belongs to the SDK. |
| `content_overrides` | Object | Deprecated compatibility map; author Message Block/Payload content instead. |
| `theme` | Object | Legacy branding compatibility data; branding is independently owned. |
| `placement_slots` | Array | Authored locations into which matching placements may render. |
| `message_blocks` | Array | Reusable content shaped for a surface template. |
| `placement_payloads` | Array | Content selections, targeting, actions, and presentation for placements. |
| `placements` | Array | Placement category, triggers, targeting, and content associations. |
| `content_promotions` | Array | Authored promotions that content and actions can reference. |
| `personalization_tokens` | Array | Named substitutions used in content. |
| `surface_templates` | Array | Presentation templates referenced by message blocks and slots. |
| `free_trial_rules` | Array | Authoring definitions for opt-in/free trial behavior. |
| `reverse_trial_rules` | Array | Authoring definitions for reverse trials and their fallback/conversion plans. |
| `objectives` | Array | Authoring-only business labels; not runtime decision inputs. |
| `plan_variations` | Array | Plan-owned pricing variations, with optional segment eligibility. |
| `addon_variations` | Array | Add-on-owned pricing variations, with optional segment eligibility. |
| `extension_rules` | Array | Tagged extension payloads; unknown mandatory kinds must be rejected by readers. |
| `seat_types` | Array | Seat-type policy definitions for account-scoped access. |
| `enforcement_defaults` | Array | Configured enforcement defaults used by applicable policies. |
| `placement_settings` | Array | Placement presentation and selection settings. |
| `segment_dimensions` | Array | Segment-dimension declarations; field presence does not imply a normalized bundle table. |
| `meter_bindings` | Array | Bindings connecting policy to meter definitions. |
| `experiments` | Array | Reserved compatibility placeholder; the current schema requires an empty array. |
| `signal_catalog` | Object | Reserved compatibility placeholder; the current schema requires an empty strict object. Signal definitions remain on the control plane and are not shipped to the browser. |

## References use the target's declared identity

Do not assume a field ending in `_id` is a database UUID. Portable references
often use handles. These examples follow the schema's reference graph:

| Referencing field | Target identity | Meaning |
| --- | --- | --- |
| Rule `entitlement_id` | Entitlement `unique_handle` | The capability this rule configures. |
| Rule `targets[].id`, kind `plan` | Plan `unique_handle` | Applicable plan. |
| Rule `targets[].id`, kind `addon` | Add-on `unique_handle` | Applicable add-on. |
| Rule segment references | Segment `handle` | Eligibility restriction. |
| Variation `plan_handle` / `addon_handle` | Parent `unique_handle` | Owning plan or add-on. |
| Variation `segment_handle` | Segment `handle` | Optional price eligibility. |
| Trial plan, fallback, or conversion references | Plan handle | Trial entry/exit plan policy. |
| Placement trigger entitlement / slot references | Entitlement handle / slot ID | Which event or location can activate the placement. |
| Payload segment-content entries | Segment handle | Conditional content selection. |
| Payload content/action references | Message block, UI path, promotion identities | Content and action to resolve. |
| Message block template reference | Surface template ID | Rendering shape. |
| UI-path promotion / placement references | Referenced promotion / placement identity | Destination or offer for the action. |

Variation-level rule target enum members exist for compatibility but are not a
recommendation to author new variation-level entitlement targeting. Use the
supported plan/add-on targeting model. Removing a segment constraint can widen
access; do not silently drop a missing reference. Validate the whole document
with the CLI before upload and review the diff before launch.

The compiler's 13 normalized bundle tables are a projection of this document,
not the complete list of Playbook body fields. A body field's presence does not
prove it is lowered into an independent table or read by every language port.
See [runtime and Playbook](/concepts/runtime-and-playbook/) for the distinction
between authored policy and the per-user facts evaluated with it.
